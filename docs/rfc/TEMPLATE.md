# <Addon> - Technical Proposal (RFC NNNN)

**Number:** RFC NNNN
**Status:** draft | in review | decided | withdrawn | superseded
**Source:** `PRD NNNN` - the requirements this answers

## 1. Decision to make

One sentence phrased as the question the review must answer - "which X do we
adopt for Y", not "we should adopt X".

## 2. Current state

How the thing works today, naming the files, tools, and config that would
change.

## 3. Options considered

One subsection per option, including the status quo and at least one
out-of-the-box candidate. Two obvious libraries is an unfinished search.

## 4. Recommendation

The recommended option, why it wins against the drivers in §1, and what
would change the recommendation.

## 5. Open questions

Unresolved points that could change the recommendation, and who or what can
answer them.

## 6. References

Related ADRs / PRDs / reports, and external sources with what each supports.

---
An RFC is the technical proposal (the "how") answering its PRD, circulated
for review; the decision it forces is recorded in an ADR of the same addon.
A spec/design/plan RFC (an addon's technical contract) embeds the options /
recommendation sections where a decision is forced. Register in
[README.md](README.md).
