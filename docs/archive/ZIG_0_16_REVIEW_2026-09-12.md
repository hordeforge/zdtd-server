## 2. Language changes

### 2.1 `@intFromFloat` deprecated (changelog: "Unary Float Builtins Forward Result Type" -> "`@floor`, `@ceil`, `@round`, `@trunc` Conversion to Integers": "*`@intFromFloat` is now redundant with `@trunc` and is therefore deprecated*")

Upgrade guide: `@intFromFloat(x)` -> `@trunc(x)`; `@intFromFloat(@ceil(x))` -> `@ceil(x)`
with an integer result type (`@ceil`/`@floor`/`@round`/`@trunc` now forward the
result type and convert to int).

Semantics are preserved. Probed locally in `/tmp`: `@intFromFloat(nan)` and
`@trunc(nan)` produced the identical `i32` value, and the fix shapes
`const a: u64 = @ceil(k); const b: u32 = @trunc(@as(f32, 7.9));` compile and
run on 0.16.0. The deliberate NaN/range trap stays; only the builtin name changes.

**P2 - `std.Io.Threaded` constructed per call inside the tick.**
`src/server/game/step.zig:556` builds a `std.Io.Threaded` (page_allocator) inside
`stepTick` purely to write the APM JSON line to stdout, then `deinit`s it. The
prompt constraint is "no new `std.Io.Threaded` per call" because `init` installs
SIGIO/SIGPIPE handlers (`lib/std/Io/Threaded.zig:1652`). This one fires on the
`apm_report_period_ticks` cadence (default 1200 ticks = 60 s,
`game/types.zig:56`), so it is an interval cost, not a per-tick one: P2.
Same shape (lower stakes, not on the tick): `src/main.zig:117` (`writeStdout`,
per CLI call, P3) and `src/server/game/net.zig:462` (per accepted connection,
explicitly justified in the comment at 456-461, P3).
